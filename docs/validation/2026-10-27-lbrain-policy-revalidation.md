# 등록된 Git 사실 정책의 변경과 재검토

전체 교정 목표는 진행 중이다. 이 기록의 범위는 이미 등록된 Git 사실 정책의 명시적 변경이다. 임의 parser·miner·redaction·접근 권한 변경의 자동 전파나 모든 파생 기억의 재계산을 완료한 것은 아니다.

## 정책 변경

서버 관리자는 기존 정책 version을 명시하고 새 정책을 공표한다. 동일 project·사실·대상·필드와 기존 표시 범위를 유지해야 하며, 새 `publication_revision`은 이전 값보다 1 커야 한다. 같은 요청 key의 재시도는 같은 receipt를 반환하고 다른 요청을 같은 key에 덮어쓰지 않는다. 동시 공표 중 하나가 먼저 성공하면 다른 하나는 기존 version 불일치로 거부된다. 과거 revision 0의 기존 정책 hash는 그대로 유지한다. 같은 설정으로 되돌려도 새 revision이므로 과거 공표와 구분된다.

공표는 새 값의 증거가 아니다. 해당 이전 정책이 만든 지지·보류 assertion의 효력을 철회하고 원문, 관찰, 기존 결과와 공표 기록은 보존한다. 다른 정책의 독립 지지가 있으면 유지한다. 그 지지가 없으면 해당 사실은 새 검증까지 현재 조회에서 제외된다. 기존 정책의 정의를 실제로 보존한 경우 공표 기록에 함께 남긴다. 이전 등록에 정의가 없으면 hash가 맞는 이전 설정을 제공해 보충할 수 있으며, 없는 내용을 추측하지 않는다.

활성 semantic 정책은 공표 전에 source capability와 현재 코드·질문·모델에 결속된 검증 profile을 확인한다. 실패하면 이전 현재 값의 효력을 먼저 바꾸지 않는다. 공표된 정책이 명시적으로 비활성인 경우에는 그 기록을 남기고 재검증을 중단한다. 이 의도적인 중단과 공표 기록 없이 비활성으로 바뀐 오류는 구분한다.

## 자동 재검토와 지연 입력

공표와 재검토 계획은 같은 transaction에 기록한다. lifecycle worker는 계획을 기존 내구성 queue에 등록하고, 새 정책으로 실제 현재 source를 읽은 결과와 verification이 결속되어야 검토 완료로 표시한다. 원천이 없거나 과거 기록만 확인한 경우에는 현재 검증으로 표시하지 않고 재시도한다. 각각의 시도와 기존 결과는 보존된다. 더 새로운 정책이 공표되면 이전 계획은 현재 정책의 완료로 취급하지 않는다.

이전 정책으로 제출된 대기 요청은 새 정책의 독립 검토가 끝나기를 기다린다. 끝나면 기존 요청을 새 요청으로 위장하지 않고 별도 결과로 연결해 원래 제안이 적용되지 않았음을 표시한다. 지연된 native 기록은 원래 source 응답과 과거 결과에 연결되며 새 정책을 지지하는 독립 근거로 승격하지 않는다. 저장 직후 응답이 사라져도 이미 commit된 결과를 재사용한다.

`fact_policy_lifecycle` 관리 CLI는 `plan`, `publish`, `receipt`를 제공한다. `plan`은 읽기 전용이며 실제 공표 시 대상과 version을 다시 검사한다. `receipt`는 설정 파일이 사라진 뒤에도 요청 key로 공표 결과를 읽는다. 독립 monitor는 재검토의 미완료·차단·기한 초과 상태를 제공한다. 실제 상주 supervisor와 외부 알림 운영은 별도 범위다.

## 값 판단의 보수적 차단

독립 값 선택 평가 v7에서 실제 모델은 확인되지 않은 외부 조건을 false로 가정해 1건을 잘못 허용했다. 정상 선택은 20/20이었지만 잘못된 허용이 있어 실패다. 모델 질문에 미확인 조건을 추정하지 말라고 추가한 개발 재검사에서도 같은 오류가 발생했다. 두 결과를 보존한다.

Python 문법으로 파싱되는 원천에 조건 분기·조건식·논리 분기 등이 있으면 현재는 모델 호출 전 보류한다. 이 방법은 안전한 분기까지 보류할 수 있고 다른 언어나 불완전한 코드 조각에 대한 일반적인 실행 분석이 아니다. 이 차단을 모델 판단의 성공으로 세지 않는다. 기존 실패 자료를 사용한 개발 재검사에서는 정상 19/20, 잘못된 허용 0건이었으며, 그 자체는 독립 통과 근거가 아니다.

다음 독립 평가 v8은 표본의 capability 이름이 잘못되어 일부 모델 호출 후 중단됐다. 해당 표본과 부분 실행을 독립 통과로 쓰지 않는다. 새 평가에서는 호출 전에 capability를 검사하고 개별 준비 실패가 다른 응답 기록을 지우지 않도록 보완했다.

새 독립 값 선택 v9는 정상 **20/20**, 잘못된 허용 **0건**, 의미 판단을 거친 거부 13건, 조건문 코드 차단 3건이다. 나머지 거부는 capability 또는 범위가 달라 코드가 차단했다. 평가 plan hash는 `sha256:f46fb3200c2fef53b619338af7deb589e87af790f0443b95412748e1c82cbe2a`, private artifact hash는 `sha256:a5f45d8d7d31627a8893dde4b13963c506e18c333836604052df55ab4cd51db3`, reported cost는 0.00031688 USD다. 새 대상 식별 v4도 정상 **20/20**, 잘못된 선택 **0건**, 의미 거부 16건으로 통과했으며 artifact hash는 `sha256:e2e76944bb91085eb5648979e12cf23cefd28c4e56aa44f5937efba2ae8b9ca6`이다. 둘 다 선택한 `perplexity/pplx-decider-flash-v1.2-20261016`의 실제 응답이며 이 표본의 통과가 모든 입력의 정확성을 보장하지는 않는다.

이후 현재 사실 reader의 철회·충돌 차단을 수정해 v9의 코드 identity는 더 이상 현재 코드에 맞지 않는다. 새 독립 v10과 수정 범위는 [현재 사실 reader 검사](2026-10-27-lbrain-canonical-reader-guard.md)에 기록한다.

## 현재 검증 범위

Ubuntu 전용 PostgreSQL·Couch에서 정책 공표, CAS 경합, source 부재와 복구, 이전 요청과 지연 native의 이력 연결, worker 중단·독립 감지·재시작, 완료 응답 유실을 검사했다. 정책 변경 초기 묶음은 **144 passed, 0 skipped**, 변경한 판단 질문과 코드 차단을 포함한 새 묶음은 **203 passed, 0 skipped in 210.11s**다. 두 묶음은 중복되므로 합산하지 않는다. 일부 검사에는 모델 응답 대역을 사용했으므로 실제 모델 품질을 입증하지 않는다.

별도 실제 모델·PostgreSQL·Couch·Neo4j 묶음은 **15 passed, 1 skipped in 115.03s**다. 실제 모델 검사 12건과 graph 검사 3건이 통과했고, graph 종료·복구 제어가 필요한 검사 1건은 skip이다. 합성 Git 원문을 바꾸지 않고 기존 정책의 `ready`를 실제 모델로 반영한 뒤, 새 정책이 같은 원문을 `failed`로 재해석하게 했다. 이후 도착한 이전 native 기록은 원래 결과에만 연결되고 현재 `failed`는 유지됐다. 두 해석의 관찰 ID는 하나이며 assertion과 이력은 각각 보존됐다. 이 검사는 실제 사용자 세션 전체나 운영 배포의 실증은 아니다.

현재 로컬 worker 전체 검사는 **5387 passed, 818 skipped in 56.53s**이고 skip을 연동 통과로 계산하지 않는다. Java `gradle test`는 BUILD SUCCESSFUL이며 해당 task는 UP-TO-DATE다. Ubuntu source bundle hash는 `sha256:44a614c051d95e523bfef02da30b9fcee3e9eaf954e78505ffc3b85e5f196350`이다. 두 profile은 이 bundle의 현재 코드 identity로 다시 로드해 확인했다. 작업 전용 OpenRouter 임시 인증 파일은 검사 뒤 삭제하고 부재를 확인했다.

운영 활성화·merge·운영 GC는 이 검증에 포함되지 않는다. 설정을 되돌릴 때도 새 공표로 처리하고 원문·관찰·이력·검토 결과의 보존 제약을 유지한다.
