# 교정된 사실에 의존하는 파생 기억의 재검토

상태: 설계와 달성 조건. 이 문서는 구현 완료의 증거가 아니다. 기존 `memory_edges`는 카드 간 `derived_from`을 저장하지만, 사실의 어느 필드와 어떤 값이 파생 내용에 사용됐는지 보장하지 않는다. 합성 PostgreSQL 진단에서는 이 관계를 명시한 파생 카드도 원래 사실이 교정된 뒤 계속 현재 조회에 나타났고 별도 재검토가 예약되지 않았다.

## 필수 계약

파생 기억을 만들거나 갱신할 때 실제로 사용한 사실 범위·필드·검증된 값과 버전, 파생 대상과 그 버전을 서버가 확인해 연결한다. 출처가 단순히 관련 있다는 사실만으로 특정 필드의 의존 관계를 만들어서는 안 된다. 기존 `derived_from` edge는 영향을 받을 후보를 찾는 근거일 수 있지만, 누락된 필드나 사용한 값을 추측하는 증거가 아니다. 관계가 없는 기존 파생물까지 모두 식별했다고 주장하지 않는다.

원래 사실의 검증된 현재 값 또는 근거 효력이 바뀌면 그 변경과 내구성 있는 영향 검토 계획을 원자적으로 연결한다. 원래 값이 유지되는 독립 근거, 다른 필드만 바뀐 경우, 같은 값의 재확인과 실제 값 변경을 구분한다. 이전 결과의 provenance와 원문은 보존한다. 과거 변경 경위를 추정하거나 `경위 미확인` 문장을 새 기억에 넣지 않는다.

등록된 의존 관계는 다단계·다중 입력·순환·중복 관계와 관계 생성 중 동시 변경을 다룬다. 검색 한도나 누락된 참조가 있으면 완전히 검토한 것으로 표시하지 않는다. 대상 또는 입력이 재검토 중 다시 바뀌면 이전 판단으로 새 내용을 덮어쓰지 않는다. 저장 직후 종료, 재시도, worker 중단 및 재시작에서 같은 변경을 중복 적용하지 않는다.

자동 재검토는 새로 확인된 입력과 해당 파생 내용의 관계를 검증해야 한다. 최신 원천이 새 내용을 직접 뒷받침할 때만 검증된 범위의 변경을 적용한다. 입력만 바뀌었다는 이유로 그 반대 주장이나 새 내용을 임의 생성하지 않는다. 의미상 동일 여부나 실제 지지가 필요한 판단은 이미 선택한 모델과 별도 검증된 적용 기준을 사용하고, 결정 가능한 identity·권한·범위·버전·현재성 검사는 코드로 처리한다. 권한이 없어지거나 근거가 불완전하면 검증된 새로운 내용을 가장하지 않는다.

원본 사실의 교정과 파생물 재검토 결과는 구분한다. 새로운 조회에서 오래된 파생 문장이 확인된 현재 사실인 것처럼 반환되지 않도록 권위 조회와 graph·cache 경로의 경계를 검사한다. 이미 전달한 prompt를 소급 수정했다고 주장하지 않는다. 우열을 가릴 수 없는 상충 사실의 B 정책은 별도 미결정이며 이 문서로 선택하지 않는다.

재검토가 지연되거나 source·모델·설정이 막히면 내구성 작업을 보존하고 자동으로 다시 시도한다. worker가 계속 살아 있어도 장기 미해결을 독립적으로 감지할 수 있어야 하며, 차단과 완료를 구분한다. 파생물과 무관한 다른 사실의 freshness를 올리지 않는다. 작업 경위나 미확인 상태를 사용자 기억에 추가하는 것으로 재검토를 대신하지 않는다.

## 검증과 완료 조건

다음 항목은 실제 구현 경로별로 각각 검증한다. 하나의 단위 검사나 합성 경로를 전체 완료로 합산하지 않는다.

1. 동일 입력 재확인, 한 필드만 변경, 값 변경, source 철회, 서로 다른 독립 입력이 남은 경우의 영향 대상을 구분한다.
2. 생성 중 원래 사실 변경, 교정 중 새 의존 관계 추가, 여러 worker와 다단계·순환 관계, 중복 key·부분 실패에서도 영향 대상이 유실되지 않는다.
3. 실제 PostgreSQL의 권위·의존 관계·재검토 결과가 transaction과 보존 제약으로 결속되고, 예전 대상에 대한 재시도가 새 결과를 덮어쓰지 않는다.
4. 실제 모델의 지지·반증·부족·무관 사례와 별도 독립 평가로 잘못된 허용과 정상 재검토를 측정한다. 모델 오류나 원천 부재는 자동 재시도와 독립 감시를 남긴다.
5. 실제 context/list/query 및 Neo4j 지연·복구, 일반 세션 수집과 backfill에서 구식 파생물이 현재 검증 결과로 부활하지 않는지 확인한다.
6. 실제 worker 종료·재시작, 장기 차단, 응답 유실 및 복원에서 관계·원래 근거·재검토 계획이 보존되고 자동으로 진행된다.

현 구현의 재현과 각 단계의 검사 증거는 [달성 추적](correction-acceptance.md)에 별도로 기록한다.
