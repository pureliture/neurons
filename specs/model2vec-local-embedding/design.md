## D1 서비스 / API / 설치

- Neurons `worker`에 optional extra `local-embedding`(model2vec==0.10.0, 서버 framework 명시적 pinned/locked)과 CLI entry point를 구현한다. 기존 worker 기본 이미지에 모델 라이브러리·가중치를 무조건 넣지 않는다. HTTP 서버는 단일 모델 프로세스/단일 worker로 시작; `uv` 설치로 플랫폼별 의존성을 재현. Mac 설치와 모델 파일 경로는 환경/CLI로 설정, 개인 경로 하드코딩 금지. 이 layout은 설계상 제안 이름이며 최종 CLI 이름은 Neurons 기존 naming contract에 맞춰 implementation에서 하나로 고정하고 README에 명시한다.
- `POST /v1/embeddings`: JSON `model`은 등록된 alias `local-model2vec-256-v1`만 수용; `input`은 비어 있지 않은 문자열 또는 비어 있지 않은 문자열 배열. `encoding_format`은 생략/`float`/`base64`만 수용한다. 생략 또는 `float`는 숫자 배열, `base64`는 256개 IEEE754 float32 little-endian bytes를 base64 문자열로 반환한다. 운영 MCP 이미지의 OpenAI SDK 3.42.0은 옵션을 생략해도 wire에 `base64`를 보내는 것을 MockTransport로 재현했다. `dimensions`는 생략 또는 256만 허용(이외 400). 배열 순서 그대로 `data`에 `object=embedding`, `index=0..N-1`, 256개 유한 성분을 반환하며 top-level `object=list`, `model=local-model2vec-256-v1`을 포함한다. Graphiti create/create_batch, PG sync SDK, bulk 원시 HTTP에 대해 실제 SDK transport·서버 통합 테스트로 float 및 base64 실수값 일치·순서·유한성을 증명한다. 성공 `usage` 필드는 다음 오류/스키마 계약에 따라 필수로 제공한다.
- API 입력/오류 계약: JSON object는 `model`, `input`, `encoding_format`, `dimensions` 및 SDK가 실제 넣는 `user`(optional string, 로깅 금지)만 허용. 중복 JSON key·알 수 없는 key·null/숫자·중첩/토큰ID 배열·빈 문자열 또는 배열 내 빈 원소·빈 배열·잘못된 JSON·`encoding_format:null`·boolean/정수 아닌 `dimensions`는 400 `invalid_request`; byte 초과 413 `input_too_large`; 허용하지 않는 model 400 `unknown_model`; 부하/10초 큐 만료 429 `capacity_exceeded`; 모델 미준비·시작 실패 503 `model_unavailable`; 내부 에러 500 `internal_error`. 429/503은 `Retry-After: 2`와 bounded retry 가능, 400/413은 자동 재시도 금지. 모든 오류는 `{"error":{"message":"<generic>","type":"invalid_request_error|rate_limit_error|server_error","param":null,"code":"<stable code>"}}`이고 원문/키/벡터/파일경로/내부 예외 미포함. 단건·배치와 실제 OpenAI 3.42.0, Graphiti async, bulk의 성공/실패 및 retry 매핑을 통합 테스트한다. 성공 `usage`는 실제 고정 tokenizer의 각 item 토큰 수 합을 `prompt_tokens`와 `total_tokens`로 반환하고, API 청구가 없음을 별도 표시한다(해당 숫자를 공급자 과금 측정치로 사용하지 않음). `livez/readyz`도 공통 envelope를 사용한다.
- `GET /livez`는 프로세스 생존만, `GET /readyz`는 로컬 고정 모델·버전·차원 검증 후 준비 여부를 반환한다. readiness는 유료 호출/운영 DB 변경 없이 동작하며 모델 미설치·불일치 시 503이다. status에는 alias/revision/dim 및 준비 상태만 노출한다. 서버의 입력·응답·인증값·에러/프록시 로그 및 평가 산출물에 원문·벡터·비밀·개인경로를 남기지 않는다.
- 서비스 요청 제한 제안: 입력 UTF-8 최대 8KiB/항목, 배치 최대 16항목·총 128KiB, JSON 전체 최대 160KiB, 동시 추론 1, 추가 대기 8, 10초 대기 만료 및 429, 오류 request 400/413, 초기화 실패/장애 503. 개발 후보값이지 실측 SLA가 아니다. input 크기 또는 총 크기 초과는 명시적 거절, 무조건 잘라내기 금지. 큐 제한에 진입 전 요청 바이트를 제한한다.
- 모든 Neurons local-model 소비자는 서버 호출 전 공통 `canonical_embedding_v1`을 사용한다: 정확한 UTF-8 바이트를 문자 경계를 보존하며 현재 offset부터 **8192 bytes 이내 최장 유효 UTF-8 접두사**로 끊고 원문 순서대로 반복한다(문자/공백 정규화·겹침·누락 없음). `input_hash`는 이 알고리즘 적용 전 전체 정확한 입력의 UTF-8 바이트 SHA-256을 소문자 `sha256:<64hex>`로 표현하며, profile ID와 대상 key를 별도로 묶는다. 입력 텍스트에 추가 직렬화/조각 정보는 해시하지 않는다. 빈 입력은 명시적 오류. 각 조각은 모델 `encode(max_length=None, normalize=True)`를 명시해 float 256 벡터를 구한다. 단일 조각은 그 벡터; 여러 조각은 각 조각의 UTF-8 byte 수로 가중합 후 L2 정규화한 벡터를 사용한다(0 norm/nonfinite는 오류). 서버의 한 item은 반드시 조각 하나이며 추측 가능한 서버 쪽 추가 분할은 금지. 단건/배치/PG/Graphiti/bulk의 공유 client adapter가 **동일한** 순서·가중·hash를 적용한다. 하나의 문서에서 조각 실패 또는 응답의 누락/중복 index/차원 오류가 발생하면 부분 벡터를 저장하지 않고 전체 identity 재시도한다. adapter는 조각 배열을 보내기 전 실제 JSON UTF-8 encoded body 길이를 계산해 160KiB를 초과하지 않도록 배치를 순서대로 더 작게 나누며, 단일 조각조차 envelope 포함 한도를 초과하면 오류로 중단한다. token usage 계산은 고정 tokenizer의 truncation을 명시적으로 해제한 결과를 사용하고 tokenizer 설정은 추론 완료 후 복원한다. 8KiB 미만이지만 512토큰이 넘는 한국어에서도 pinned tokenizer와 실제 model encode의 max_length=None을 검증하고, 멀티바이트 경계·본문 첫/중간/끝의 변화·장문 검색을 테스트한다. 길이 분할 알고리즘/가중/정규화의 변화는 새 profile이다. 서비스는 이 내부 조각 프로토콜에 한정되므로 예전 SDK 호출을 URL만 바꾸어 직결하지 않는다.
- API 서버는 기본 127.0.0.1 loopback만 수신. 운영 후보 경로는 `Neurons Pod → 기존 cluster egress/SNAT 또는 승인된 private proxy → Tailscale에서 관측되는 노드 identity → Mac Tailscale Serve HTTPS → 127.0.0.1 서비스`다. Mac 노드의 tailnet 인증과 Serve TLS가 전송/노드 신원 경계이며 **개별 Pod identity를 증명하지 않는다**. Atlas는 현재 경로·소스 노드·DNS/포트·TLS CA/신뢰·Serve 및 tailnet policy를 read-only로 먼저 확인하고 해당 노드만 허용 가능한지 증명한다. 기존 노드 단위 단일 사용자 환경이면 별도 사용자/서비스 계정을 강제하지 않는다. 접근 주체가 기대한 노드와 다르거나 우회가 가능하거나 기존 정책으로 차단할 수 없으면 운영 적용을 중단하고 최소 변경안을 별도 승인받는다. 허용된 기존 Pod 성공, 비인가 노드/경로 거절, TLS/DNS 실패, 연결 두절, 서비스 loopback 외 직접 접근 불가를 검증하며 위조 header를 identity로 신뢰하지 않는다. 현재 실행 중인 Tailscale은 Running, 현재 Serve 설정에 public funnel은 관측되지 않았으나 Model2Vec 신규 라우트 자체는 미구성·미검증이다. 네트워크/ACL/시크릿 변경은 운영 별도 승인이다. `launchd` user agent는 로그인 세션 의존; 로그아웃·재부팅·절전 복구를 측정해 운영 가용성을 확정하고 사용자에게 영향/수동 복구를 고지한다.
- Mac 자원 1.93GiB 실측 peak이며 상시 RSS 아님. 초기 서비스 관찰 상한 가정 3GiB; host 보호 알림/자동 제한 가능성 및 긴 문장 고부하와 host 다른 서비스 간섭을 측정해 승인한다. 3GiB를 OS가 강제로 보장하는 macOS limit으로 주장하지 않는다. 기존 Ollama Cloud 구성/키/서비스는 변경 금지.

## D2 프로필과 PG 물리 모델

- 불변 profile descriptor: profile_id, model repository+immutable revision+weights digest, `model2vec` version, 256차원, cosine, normalization·encoding·긴 입력 처리 버전, `input_role` 및 canonical input algorithm. 하나라도 바뀌면 새로운 profile_id. 비교 가능한 벡터만 같은 프로필로 둔다. 임의 0-padding, 기존 3072 ->256 투영 또는 서로 다른 모델 점수 혼합 금지.
- Additive 저장: 기존 `memory_cards.embedding` 및 `session_memory_chunks.embedding`을 유지. 별도 `card_local_embeddings(memory_id FK, profile_id, source_content_hash, input_hash, vector vector(256), state, updated_at, PRIMARY KEY(memory_id,profile_id))`와 `session_local_embeddings(chunk_id FK, 동일 필드, PRIMARY KEY(chunk_id,profile_id))` 제안. 실제 FK 타입·schema/index·삭제 정책은 d8acb36 catalog 확인하여 명시한 migration으로 구현, cascade로 원본 지우지 않는다. `ready`에는 non-null 256차원 finite nonzero vector; cosine HNSW 인덱스 별도. 통합 실제 PG 17/pgvector 에서 유효성, 권한, lock·롤백을 검증. 프로필 존재 규칙은 정적 상수/제약으로 보증한다.
- Source 입력 계약은 모든 카드 writer가 동일 helper `card_input_v1`를 사용: `summary`가 비어 있지 않으면 summary, 아니면 title, 그것도 비었으면 `typed_payload`를 `json.dumps(ensure_ascii=False,sort_keys=True,separators=(',',':'),allow_nan=False)`로 직렬화한다. 승인 경로의 기존 summary-only 분기도 local profile에서 helper를 사용하고, 빈/invalid 결과는 오류로 남긴다. 세션 입력은 `content_markdown`이며 기존 프로필 포함 chunk_id를 새 profile로 만들어 원본 세션을 중복 생성하지 않는다. 원본 `content_hash`와 정확히 임베딩된 전체 입력 `input_hash`를 모두 저장하고 enqueue/CAS/search JOIN/재색인에 같은 helper를 사용한다. helper 결정이 과거 Gemini 입력과 동일하다는 보장은 없으며 기존 구 프로필 벡터·receipt는 변경하지 않는다.
- 현 `PgSessionMemoryProjector.project()`는 Gemini 임베딩 완료 후 구 컬럼과 profile 기반 chunk_id를 쓰므로 단순 endpoint 변경은 금지한다. **주의: `session_memory_chunks`에는 source_hash 열이 없다.** 기존 ID를 찾기 위해 raw source_hash를 해당 테이블에서 조회할 수 있다고 가정하지 않는다. 새 수집이 source_hash를 제공하면 기존의 `_derive_pg_chunk_id_impl`을 기존 프로필 두 개(`lbrain-memory-gemini-embedding-2-v1`, bounded v2)에 대해 계산해 두 candidate chunk_id를 조회하고 project/provider/session_id_hash/content_hash 및 실제 body 일치를 재검증한다. 이전 `find_ready_chunk_by_identity`의 source-independent reuse 계약도 같은 잠금 아래 확인한다. 두 hash 후보만으로 중복 부재를 단정하지 않고 project/provider/session_id_hash/content_hash 자연 범위에 해당하는 모든 기존 row(ready/pending/failed 및 bounded 이력·비표준 ID 포함)를 조회해 body까지 대조한다. 동일 body 및 scope의 단일 legacy row만 존재하고 source-independent reuse 조건에 부합할 때만 재사용한다. 8192 bytes 초과에 과거 bounded 정책이 재사용을 건너뛰었다는 사실을 보존하고, 서로 다른 source일 가능성을 해소할 source 증거가 없으면 긴 동일 body를 자동 병합하지 않는다. 기존 `local_v1` row가 있으면 우선 선택한다. 복수·미확인 row는 임의로 선택·병합하지 않으며, 안전하게 재사용할 단일 row가 확정되지 않고 `local_v1`도 없으면 현재 `source_hash`에 결합한 새 versioned `local_v1` row를 생성해 receipt의 `session_memory_knowledge_id`가 가리키는 권위 row로 사용한다. 기존 row는 삭제·수정·병합하지 않으며, receipt의 `session_memory_knowledge_id`와 일치하지 않는 row는 recall에서 제외하고 미결합 row 정리는 GC 책임으로 둔다. 누락 `source_hash`는 source-bound ID를 만들 수 없으므로 오류로 거부한다. 이미 PG에 있는 과거 row 백필은 저장된 `chunk_id`를 그대로 참조해 수행하며 source_hash 재구성이 필수라고 가정하지 않는다. identity별 advisory lock 아래 후보 부재를 재확인하고 원문/메타데이터 저장과 local job enqueue는 한 transaction에서 수행, 구 Gemini embedding 컬럼은 변경하지 않는다. 모델 불가 시에도 원문 저장과 durable local enqueue는 가능해야 한다. 구 writer가 이 계약을 지키지 않으므로 모든 구 writer를 배포 전부터 fencing/중지한 뒤 신 writer로 교체해야 하며 구·신 rolling 동시 쓰기는 금지한다. 구 버전이 살아 있을 때 local writer는 시작 실패한다. 작업 대상과 drain/readback 절차는 운영 승인 전에 확인한다.
- **Representation receipt 호환성**: d8acb36 `valid_representation_receipt()` v2는 Gemini profile과 `_derive_pg_chunk_id_impl()` 결과를 묶는다. v1/v2 validator·receipt 및 저장된 Gemini 참조는 그대로 보존하고 local 전용 receipt v3를 **별도의 profile-scoped record**에 추가한다. 기존 receipt/state 필드가 한 개뿐이므로 overwrite하지 않으며 local reader/materializer는 `(source identity, profile_id)`로 새 record를 조회하도록 명시적으로 확장한다. 기존 reader는 기존 필드·v1/v2만 사용한다. 별도 record의 저장소·문서 key가 현재 CouchDB 상태 갱신 충돌 검출과 호환되는지 실제 isolated source store에서 증명한다. v3 digest 대상은 `receipt_version=3`, `representation_kind`, `project`, `provider`, `session_id_hash`, `active_content_hash`, `projected_source_hash`, `representation_content_hash`, 실제 보존한 `session_memory_knowledge_id`, `identity_scheme`(`legacy_exact`/`legacy_reuse`/`local_v1`), `embedding_profile`, `input_hash`의 명시적 필드 목록이다. 이 목록만 sorted compact JSON(`ensure_ascii=False`, separators `(',',':')`, UTF-8)으로 직렬화해 SHA-256을 `sha256:<64hex>`로 계산하여 **별도 결과 필드** `provenance_digest`에 저장한다. `provenance_digest` 자신은 digest 입력에 절대 포함하지 않는다. 필수 필드 누락·중복/알 수 없는 필드·비정규 hash를 거절한다. `legacy_exact`은 해당 source와 실제 old-profile ID 계산이 일치해야 하고, `legacy_reuse`는 source-independent 기존 reuse 판정에 사용한 scope/body hash·DB row의 정확한 일치를 추가로 검증한다. `local_v1`은 versioned identity 계산 결과와 PG row가 같아야 한다. 모든 v3는 current source/materialization CAS와 실제 PG row의 scope/body/hash 및 local 벡터 identity를 확인하고 단순 receipt hash를 증명으로 오해하지 않는다. source materializer의 receipt read/write/currentness·qdrant_couchdb_authority 등 모든 validator 호출자에 v1/v2/v3 분기 및 unknown fail-closed를 적용, 구 receipt를 새 버전으로 relabel하지 않는다. PG와 CouchDB commit은 분산 원자성이 없으므로 PG row/job readback + source currentness CAS 후 receipt 확정하고, 어느 쪽 commit 결과 불명 시 readback/reconcile; 임의 중복 생성 금지. fixture는 v1/v2 immutability, v3 세 identity, legacy reuse, tampered profile/hash/source·변경 중 retry·out-of-order를 실제 isolated PG + disposable source store에서 검증한다.
- 삭제 정책: 새 local 벡터 테이블의 FK는 해당 부모에 한해 `ON DELETE CASCADE`로, 기존 원본 삭제가 허용될 때 파생 벡터만 제거한다(부모를 역방향 삭제하지 않음). 기존 참조 관계의 delete restriction은 유지. 다형 outbox에는 실재하지 않는 공통 FK를 만들지 않는다. 대신 per-target incarnation/generation을 명시한 durable tombstone과 job invalidation을 사용해 삭제 후 같은 ID 재생성을 구분한다. 삭제·enqueue·claim·complete는 모두 **아래 정의한 identity advisory → target advisory → queue → 부모 → 파생 순서**로 접근하며 여러 대상은 정렬 순서를 고정한다. 삭제 시 대상 local queued/processing/failed를 취소하고 incarnation을 증가시킨 뒤 부모 삭제·cascade를 동일 transaction에서 처리한다. In-flight 작업은 종료 시 incarnation/fence가 다르면 폐기; 부모가 원래 FK로 삭제 불가하면 전체 transaction rollback. 충돌/40P01/serialization 오류는 유계 retry, PG test에서 claim/완료/삭제/재생성 교차 및 deadlock을 검증한다. 이 보장은 모든 기존 삭제 writer를 조사·수정해 공통 lock을 쓸 때에만 성립한다.
- Local-profile 작업 큐는 기존 Gemini `embedding_outbox`와 분리, 유일성 `(target_type,target_id,profile_id,source_content_hash,input_hash,incarnation)` 단 active queued/processing/failed에 적용. target_type은 `memory_card`/`session_chunk`만 허용하며 다형 ID의 부모 유효성은 advisory lock 후 부모 readback으로 검증한다(단일 FK라고 주장하지 않음). 상태 `queued/processing/completed/cas_skipped/failed/dead_letter/cancelled` 외 거절; bounded retry, 다음 시도시간·attempt 및 매 claim마다 다른 fencing token·worker ID·lease expiry. claim은 queue의 대상 후보를 잠금 없이 bounded scan한 뒤 아래 정의한 identity lock과 target advisory lock을 순서대로 획득하고 queue row를 `FOR UPDATE SKIP LOCKED`로 재확인한다. 후보가 이미 바뀌었으면 skip, starvation/다중 worker/lease 만료를 실제 DB에서 검증. 원본 변경/승인과 local enqueue 또는 durable change-log를 동일 PG 트랜잭션에서 확정; 모든 실제 writer를 맵핑해 테스트한다. 구 outbox에 256 결과를 억지로 쓰거나 Gemini job을 새 profile로 소비하지 않는다.
- 잠금 전역 순서: 세션의 논리 identity lock은 canonical JSON array `["session",project,provider,session_id_hash,content_hash]`, 카드의 identity lock은 `["card",memory_id]`를 UTF-8/`ensure_ascii=False`/compact separator로 직렬화한 SHA-256 첫 8 bytes의 big-endian signed int64 값으로 생성한다(문자열에 NUL을 넣지 않음). identity lock을 먼저 잡고(여러 키는 사전순), 확정된 `(target_type,target_id)` target advisory lock, queue row, 부모 row, 파생 row 순서로만 잡는다. claim의 unlocked candidate scan은 어떤 row lock도 잡지 않고, 해당 부모 scope를 읽어 identity를 계산한 뒤 identity→target→queue를 순서대로 lock하고 모든 값을 재검증한다. 모델 호출 뒤 complete도 동일 순서다. identity가 그동안 바뀌었거나 대상이 사라졌으면 재시도/취소하고 역순 lock을 잡지 않는다. 수정 전후 identity가 다르면 두 identity lock을 정렬해 선점한 뒤 변경한다. advisory hash 충돌은 과도한 직렬화만 발생해야 하며 identity 검증을 대체하지 않는다. 실제 PG에서 새 대상 동시 생성·삭제 실패 rollback·재생성 후 늦은 완료·claim/완료 교차 및 교착 유계 retry를 테스트한다.
- 모델 호출은 DB 트랜잭션 밖. 완료 트랜잭션은 위 **identity advisory → target advisory → queue row → 부모 row → 파생 row** 순서로 lock, lease·fence·profile·source hash·input hash 및 target 권한/삭제상태 확인 후 local vector 갱신과 job completion을 원자적으로 수행. 늦은 worker는 write 금지, 원본 갱신이면 skip 후 최신 job 보장. unknown commit은 target과 job을 readback해 분류한다. 권위 원본 및 Gemini 컬럼은 쓰지 않는다.
- dead-letter 재가동: Mac 서비스가 복구된 뒤 Atlas가 aggregate `failure_code`, 대상 현재성·profile/source/input hash, retry 횟수 및 중복 활성 job을 확인한다. 일시적 model_unavailable/timeout/capacity 에러는 유한한 별도 운영 승인된 재시도 budget으로 requeue; invalid input/권한/profile mismatch/size는 오류 수정 전 자동 재큐잉 금지. requeue는 identity→target→queue 잠금과 incarnation/currentness 확인 하에서 idempotent이고 완료/구 profile job은 변경하지 않는다. 죽은 작업의 무제한 자동 재큐잉 금지.
- 검색은 local ready + 원본 source hash/input hash 일치 + 동일 profile을 JOIN하고 기존 project, authorization, currentness, temporal/authority 필터를 보존한다. 구/신 벡터를 혼합 rank 하지 않는다. coverage 불충분한 경우 또는 Mac 장애는 다음 D5 정책 적용. 현재 Graphiti/PG model failure semantics가 불명확한 지점은 기존 예외를 덮어쓰지 않고 실제 public MCP 테스트로 계약 고정.

## D3 Graphiti / Neo4j

- 운영 Graphiti 0.30.1 Neo4j search는 `n.name_embedding`/`e.fact_embedding`의 cosine 직접 계산이며 기존 Neo4j VECTOR 인덱스는 0. Graphiti 기본 저장·검색이 새 프로퍼티를 자동 선택한다고 가정하지 않는다. 엔티티 및 관계 생성·업데이트, entity resolution/dedupe, 검색, bulk writer와 모든 source path에서 read/write property를 명시적으로 분리해야 한다.
- 선택한 분리: 각 기존 Entity에 `name_embedding_model2vec_v1`, 각 RELATES_TO에 `fact_embedding_model2vec_v1` 및 같은 트랜잭션으로 canonical text hash·profile ID를 보관. 기존 `name_embedding`/`fact_embedding`과 labels, UUID, group_id, provenance, validity, relations는 그대로 보존한다. Neo4j property 에 source 관련 값은 secret/raw path 포함하지 않으며 hash와 profile 및 vector만 기록. 운영 Neo4j 고정 version 그대로; Neo4j DB 업그레이드/기존 속성 삭제/그래프 재추출은 범위 밖.
- Graphiti 커스텀 driver/search/write adapter는 두 property의 데이터 생성·업데이트·검색·중복 판정 및 community/episode 경로 존재 여부를 전수 매핑하고 기존 full-text 결합·project/group·시간·PG authority join을 유지한다. 필수 속성의 존재+size 256+profile+hash/currentness 사전 필터 후 cosine; 768/3072/누락은 이전 값 변형 없이 제외하고 aggregate gap으로 관찰. property 이름은 allowlisted 상수로 고정, 동적 query injection 방지. 검색 응답이 있다는 것만으로 vector branch 성공으로 판정하지 말 것. 필요하면 처음에는 exact cosine으로 시작하고 운영 데이터 규모에서 시간/부하 측정; 벡터 인덱스 추가는 필요성과 filter correctness를 검증한 별도 승인 대상이다.
- **구현 경계 결정**: Graphiti 0.30.1 고정 버전의 최소 유지보수 fork를 Neurons 레포 안에 vendoring하고 upstream LICENSE/NOTICE 및 수정을 기록하며 패키지 빌드에서 하나의 배포판만 설치한다. 런타임 monkeypatch 금지. 런타임 설치 라이브러리 검사 결과 `get_relevant_nodes`, `get_relevant_edges`, `get_edge_invalidation_candidates`가 기존 속성을 직접 조회하므로 Neo4j driver 검색 인터페이스 주입만으로는 불충분하다. fork에는 local-profile 전용 명시적 policy/operations를 추가하고 upstream `graphiti_core`의 관련 call sites를 연결한다. 기존 profile은 기존 경로 그대로 유지. 수정 전후 전체 callgraph/버전별 fingerprint를 문서화하고 미지원 vector-sensitive 경로는 fail closed, silent upstream fallback 금지. upstream license compliance와 wheel import provenance/digest·build 및 이후 업데이트 계획이 검증되지 않으면 구현 수용 불가.
- **필수 경로 매핑**: (1) 일반 검색 `search_ops`의 node/edge cosine과 fulltext+RRF는 새 속성 256만 비교하며 group/time/limit/episode 조회/PG join을 유지한다. (2) `search_utils.get_relevant_nodes`=entity resolution, `get_relevant_edges`=edge dedupe, `get_edge_invalidation_candidates`=시간 무효화 후보의 직접 Cypher를 profile-aware로 교체한다. (3) `EntityNode.save`/`EntityEdge.save`, `bulk_utils` 및 Neurons `bulk_semantic.py`의 단건/벌크 생성·변경은 기존 embedding 필드를 절대 overwrite하지 않고 local property+profile/input hash를 atomic write 혹은 동 transaction 무효화+durable graph-local job으로 기록. loader는 local profile에서만 내부 `name_embedding`/`fact_embedding`에 새 값 매핑; 기존 property의 자동 접근 방지. (4) Community는 local mode에서 기능을 명시 비활성하고 그 노드/검색/생성 접근은 fail-closed 오류로 표시하며, 0개라는 과거 통계를 근거로 조용히 무시하지 않는다. 위 각 경로의 정확한 호출자·함수·return model·미지원 실패 테스트 매트릭스를 구현 PR에 포함한다.
- **기존 개체 후보 coverage**: 기존 graph의 local 속성이 아직 없는 동안 entity/edge dedupe를 수행하면 중복 생성을 유발한다. 따라서 그래프 백필 전과 동안 entity 추출 writer를 중지/대기시키고 내구 cursor/outbox를 유지하며, 일반 원문 ingest·권위 PG write는 계속한다. source 변경/생성은 별도 durable graph outbox에 쌓는다. 동일 group에 대한 100% 현재 및 지원되는 역사 candidate coverage와 최종 catchup이 검증된 후에만 해당 group graph writer를 순차적으로 재개한다. 운영 외부 서비스 중단이 발생하는 경우 별도 승인; 임의로 '동등 검색'이라 가정하지 않는다. 읽기 전환도 coverage gate 후에만 허용한다.
- **재개 후 group 동시성 및 crash 복구**: group별 Neo4j `EmbeddingGroupFence` marker(고유 group_id 제약, monotonic epoch, active/pending/degraded)를 정본으로 사용한다. 하나의 group에 하나의 local graph writer만 lease를 얻어 entity/edge candidate read→dedupe→저장을 순차 진행한다. 작업 중 node/edge write·bulk write·invalidation의 모든 Neo4j transaction은 marker의 쓰기 잠금을 먼저 얻고 현재 epoch/holder 유효성을 확인한 뒤 변경; lease takeover 시 marker epoch를 같은 lock 아래 증가시키므로 구 worker의 늦은 commit은 거절된다. Lease 만료 판단 시계/renewal, lock owner와 직접 Cypher bypass 차단을 구체 구현하고 다른 group의 처리 및 PG 원본 저장은 막지 않는다. 동일 group 내 pending local embedding·미확인 vector 또는 partial graph mutation이 있으면 추가 dedupe/create를 중단하고 재조정한다. 수정 변경과 `embedding_dirty=true`/input hash/profile을 **같은 Neo4j transaction**에서 기록하므로 graph commit 이후 PG job enqueue 전에 crash해도 dirty 상태가 남는다. 재조정 worker는 group별 dirty 스캔 + 기존 PG graph outbox pending을 독립 재조회해 idempotent `(group,element UUID,profile,current_input_hash)` job을 생성한다. PG job 완료는 Neo4j의 lock-first 현재 hash/profile/valid vector readback 이후만 ack하고, graph 미확인·PG ack 미확인·unknown commit에는 각 저장소 readback→재시도하며 재실행해도 권위 graph를 중복 생성하지 않는다. Graph side에서 dirty가 외부 race 없이 clear되기 전에는 해당 group 계속 gated. group marker를 모든 사용자가 접근 가능한 공개 기능으로 노출하지 않고 기존 graph 원본과 구 벡터는 보존한다. 원문 저장/PG commit과 Neo4j는 분산 원자적이라고 주장하지 않는다. 경쟁 신규 entity 2개, 느린/만료 worker의 늦은 저장, graph-commit 전후/PG enqueue 전후/ack 전 crash, 순서 뒤집힘 및 batch 실패를 실제 격리 PG+Neo4j+fork로 interleave해 검증한다.
- **Graph delete tombstone**: Entity/RELATES_TO 삭제는 group fence/epoch 검증 후, 같은 Neo4j transaction에서 삭제 대상과 독립적인 `EmbeddingDeletion` record를 먼저 idempotent MERGE하고 대상 삭제를 수행한다. record key는 `(group_id, element_kind, UUID, incarnation, delete_operation_id)`이고 profile/source revision/input hash, 삭제 이전 element ID·상태와 created/ack 상태만 기록하며 기존 raw text/비밀은 저장하지 않는다. 요소 삭제와 record 생성은 함께 commit/rollback된다. 삭제 직후 crash라도 record는 남고 reconciler가 이를 scan해 PG graph/local job 및 해당 속성 제거 여부를 확인한 후 idempotent ack한다. 같은 UUID의 재생성은 새 incarnation으로 구분하며 늦은 작업이 이전 incarnation을 되살리지 못한다. 기존 수집원/PG outbox가 이미 갖고 있는 삭제 동작을 대체한다는 주장은 하지 않고 양쪽 증거를 조정한다. tombstone 보존·정리(데이터 삭제)는 별도 승인 대상이다. 테스트는 delete commit 직전/직후 crash, 관계/노드 detach delete, delete→same UUID recreate, 늦은 job, graph-only record/PG-only task를 포함한다.
- **Graph operation journal**: 각 episode projection마다 `(source_type,source_id,source_revision,group_id,profile_id)`와 task kind로 결정되는 operation_id를 사용해 source outbox와 PG journal의 unique row를 한 PG transaction에서 먼저 기록한다. LLM 추출이 필요한 경우 첫 graph mutation 이전에 redaction 검사를 통과한 확정 실행 계획(생성·갱신·무효화될 node/edge UUID와 필요한 최소 파생 payload 및 그 hash)을 private PG에 내구 기록하고, retry는 같은 계획을 재사용한다. raw transcript·비밀이나 불필요한 모델 입력을 기록하지 않고, 해당 계획의 프라이버시 게이트·접근 및 보존 정책을 먼저 검증하며 조건 불충족이면 graph mutation 금지다. 각 graph transaction은 group marker epoch를 먼저 lock/검증하고 `(operation_id,step_id,effect_hash)` receipt를 graph에 기록해 중복 수행 시 일치하면 no-op, 불일치면 quarantine한다. 다중 transaction 처리에는 전체 단계 목록·상태가 journal에 남아야 하며, 결과 미확정은 graph receipt와 실제 node/edge effect readback으로 해당 step만 조정한다. Neo4j 단계들이 모두 확인되고 현재 source revision/hash와 dirty/tombstone coverage가 일치하기 전에는 source PG graph outbox를 acknowledge하거나 group gate를 해제하지 않는다. graph 완료 후 PG ack 실패는 readback 재시도, 계획 기록 전 실패는 재계획 가능하나 graph mutation이 없어야 하며, 중간 crash/재시작 시 저장된 immutable 계획·step receipt를 기준으로 나머지만 재실행한다. 다중 저장소 atomic/정확히 한 번 모델 호출을 주장하지 않는다. 격리 PG+Neo4j fixture는 첫 노드/중간 edge/무효화/마지막 step·ack 각각 전후 crash, 재시작, 변경 source 및 그룹 epoch takeover를 강제로 검증한다.
- **Graph CAS lock-before-read**: 모델 계산은 transaction 밖에서 한다. 같은 Neo4j 트랜잭션에서 대상 UUID를 찾고 write lock을 강제로 먼저 획득(검증된 transient 전용 lock property의 SET→REMOVE 방식 또는 버전에서 검증된 동등 방식; 기존 property 충돌 시 fail-closed), 그 후 다시 UUID·존재·canonical name/fact·입력 hash·profile을 읽어 vector/hash/profile을 함께 쓴다. 모든 신 writer가 같은 lock-first+원본 변경 시 새 속성 원자적 무효화/재처리 규칙을 따른다. old writer가 실행 중이면 백필·새 writer 금지. 대상 삭제/경쟁 시 skip + durable retry, unknown commit은 해당 graph property와 큐 readback 후 분류한다. PG graph job 완료와 Neo4j 반영은 별개이며 cross-store reconciliation 및 두 트랜잭션 교차 fixture로 검증한다.
- Graphiti 업스트림 pin 0.30.1과 Neo4j 5.26.x 실제 런타임 검증. 격리 Neo4j 테스트에서 3072·768·256·null 혼재, node/edge write, dedupe, vector/fulltext, 동시 수정, group isolation, timestamps/provenance, PG join, no-network 모델을 실증한다. community가 0이라는 과거 관측을 미래 부재로 가정하지 않는다. 모든 writer가 새 속성을 정확히 쓰고 구 속성 보존함을 검증. upstream 내부 monkeypatch만으로 지속 가능성을 주장하지 않는다.

## D4 백필과 전환

- 생성 전 inventory: PG 카드·세션, Neo4j Entity·RELATES_TO의 source hash·text 존재·profile별 coverage를 집계; 조회 범위 외 원문·키는 출력하지 않는다. graph canonical source는 Entity name / RELATES_TO fact로 실제 graph write 및 검색과 일치시키고 revision hash를 계산한다. source 부재·잘못된 텍스트는 quarantined/failed, 완료로 치지 않는다.
- PG/Neo4j 별도의 제한 one-shot worker: deterministic keyset(cursor), explicit target/profile/image/version/time budget, 초기 batch=100 상한·concurrency=1 후보(운영 전 검증), durable progress; cursor만 전진시키고 work 잊는 형태 금지. 원본 스냅샷 count와 각 대상의 key+current content/input hash를 기록, enqueue+checkpoint는 PG에서 원자적; PG/Neo4j cross-store exactly-once 보장 주장 금지. graph 대상은 graph의 실제 현재 input hash를 확인해 단일 transaction 내 local property CAS; concurrent update/delete 시 skip/재시도, 재실행 멱등. 각 lane별 examined/current/ready/pending/failed/quarantine·새로운 source 변화분을 보고하고 anti-join/reconciliation으로 현재 대상 누락 0을 증명한다. fail/dead-letter를 성공으로 취급하지 않는다.
- 안정화: 새 local writer 활성화 후 백필 기간 동안 변화하는 source를 durable하게 수집하고 마지막 reconciliation한다. 실제 기존 writer가 새 속성을 유지·갱신하도록 수정 전환하지 못하면 운영 cutover 금지. PG 원본의 'current' eligibility는 기존 authority 법칙을 따른다. PG와 Neo4j 각각 frozen high-water 범위와 catchup 범위를 분리해 검증한다.
- 검색 전환 Gate: 데이터 100%를 분모에서 임의 제외하지 않는다. 대상은 현재 card/세션뿐 아니라 실제 `as_of`/`include_historical` 및 graph valid-time이 지원하는 과거 검색 대상까지 포함해 `current`, `historical-supported`, `failed`, `quarantine`, `retired-outside-supported-scope` 집합으로 분류한다. `current`+`historical-supported` 각각 eligible 준비율 100%, unclassified=0, 중요한 누락/오류 0, failed/quarantine 공개·명시적 사용자 수용 없이는 전환 금지. 전환 직전 구 writer/유료 consumer fence 및 in-flight drain 확인 후 최종 watermark를 고정, 새 writer의 내구 변경기록을 catch-up·anti-join으로 소진하고 reader cutover 제어값과 재검증 경계 사이의 새 insert/update/delete가 누락되지 않는지 fence 또는 이중 기록으로 보장한다. 전환 직전·직후 insert/update/delete 및 historical as_of를 포함한 exact set comparison 테스트가 필요. 실제 target 및 excluded 정의는 read-only inventory와 사용자 승인으로 고정한다. 하나의 count 일치만으로 합격 아님.

## D5 장애 / cutover / rollback

- Mac 불가/미준비: local endpoint fail closed; 유료 외부 임베딩 fallback 없음. 신규 벡터 필요 작업은 durable bounded retry/backoff 후 dead-letter, canonical 저장/이미 완료된 데이터 삭제 금지. 검색: local vector가 필요한 public query는 기존 제품의 명시 상태 체계를 사용하여 degraded/unavailable을 표시하고, 가능한 경우 오직 검증된 model-free lexical/authorized context 경로만 이용한다. 안전한 lexical 경로가 없다면 결과 없음/서비스 불가를 명시하며 멋대로 의미검색 정상이라고 표시하지 않는다. context/list가 임베딩 불필요한지 실제 dispatcher로 검증. Mac 복구 후 대기 작업이 누락/중복 없이 재개됨을 실증한다.
- 서비스 변경은 Mac 배포와 클러스터 소비자 라우팅 모두 포함. 비용 0 보장은 이전 Gemini route 동시 유입까지 차단한 이후 모든 실제 caller의 라우팅/클라우드 사용량 및 브리지 장부를 관측해 검증. 브리지 우회 직접호출 및 다른 프로젝트는 별도 확인, 0 트래픽 자체를 기능 정상으로 해석 금지.
- 순서: 구현·격리 증명 → 명시 운영 승인 → Mac private 서비스(기존 트래픽 영향 없음) → 구 Gemini 호출 inventory/신규 enqueue 차단·consumer 일시중지·in-flight drain 및 API egress 차단 → additive DB/graph 스키마 및 신 writer 배포 → 제한 백필·catchup → 검증 게이트 → reader 전환 → 실제 MCP·writer·cost 확인. 구 Gemini 대기 job은 삭제/변경 없이 보존·격리하고 기존 writer/consumer가 자동 재개하지 못하도록 운영/소스 양쪽 경계에서 fence한다. 구 writer가 새 lock 규약을 지원하지 않으므로 구·신 동시 write 금지, 전환 유휴 시간과 데이터 입력 영향 실측 후 승인. 모든 구 enqueue 및 직접 호출 경로와 이전 in-flight가 0인지 확인하기 전에는 비용 0을 주장하지 않는다. 각 운영 단계는 정확한 대상과 승인, 중단점·예상 일시영향, 임시 파일/인덱스 및 readback 명시. 프로덕션 변경 및 기존 데이터 삭제는 기존 승인 정책을 따른다.
- 사용자 결과 나빠지거나 오류/누락 발생 시 local 모델 호출과 vector writes를 중지하되 원문 저장과 새로운 revision의 durable enqueue/change-log 기록은 유지하고, 실패·중단 기간 발생분은 local 재개 때 source anti-join으로 catch-up한다. 원문과 양쪽 벡터 보존·사용자에 검색 제한 알림. 기존 Gemini 프로필로 되돌리는 것과 유료 호출 복원은 별개: 승인 없이 Gemini 호출은 계속 차단하고 기존 vector만으로 정상 semantic search가 가능하다고 주장하지 않는다. 구 writer는 신 writer가 중지·펜싱된 것이 확인되기 전 재가동하지 않는다. 복구는 local path 우선; 유료 Gemini 재활성화는 비용·범위별 별도 명시 승인.

## D6 Acceptance (제안한 기준 — 사용자 승인 전)

- 격리 서비스: model revision/hash and 256 finite, wrong model/input/dim/oversize rejected, 단건/배열 index ordering, 길이 손실 방지, queue/max request/timeouts, overload/restart/offline and no remote egress; 실제 SDK·Graphiti·bulk client regression.
- 격리 PG: old vector/authority immutable, new profile state/identity, two concurrent claim lease fencing, source update/delete race, enqueue transaction+cursor crash, interrupted restart, stale/backfill anti-join, role/project/time authorization filters, no paid fallback. 실제 PostgreSQL+pgvector; fake DB만 금지.
- 격리 Neo4j + PG: 3072/768/null/256 혼재 fixture, actual create/update/search/dedupe/bulk, community check, fulltext+local vector, group/time/provenance+PG authorization join, update/delete race, missing model+degraded public MCP. 실제 Graphiti 0.30.1 및 지정 Neo4j 5.26.x, cloud denied, live DB 아님. 그래프 검색 응답 내 vector branch 실행 증거 별도.

## P3-1 session-memory segment_v1

기본 `SESSION_MEMORY_REPRESENTATION=session_v1`의 본문·hash·projection은 그대로 둔다. `segment_v1`은 local profile에서만 사용하며, materializer의 턴 순서 view를 `SESSION_MEMORY_SEGMENT_MAX_BYTES`(기본 4096) 경계로 묶고 tool evidence는 마지막 segment에 붙인다. segment ID는 `segment_v1`, project, provider, session hash, segment 본문 hash, max bytes로 결정한다. 본문이 바뀌면 ID도 바뀌며 append 시 본문이 그대로인 prefix segment는 재사용한다.

segment 하나를 기존 `session_memory_chunks` row 하나와 local outbox job 하나로 저장한다. scope/body 및 ready vector가 검증된 row는 재사용하고 schema 변경·stale 표시·GC는 하지 않는다. profile-scoped receipt v4는 ordered `segment_ids`와 digest를 권위로 기록하며, 호환용 knowledge ID는 첫 segment ID다. 현재성 CAS와 source revision fence는 유지한다. 검색은 receipt가 허가한 segment만 세션별 한 card로 묶고 점수에서 `SESSION_MEMORY_SEGMENT_LENGTH_PENALTY`(기본 0.01) × `ln(segment 수)`를 뺀다. 본문은 최고 hit과 같은 세션의 앞뒤 segment만 포함한다.

## P3-2 shadow recall candidate pools

Shadow 지표는 실제 bounded recall 후보 풀을 사용한다. M0는 세션 행을 유사도 순으로 정렬해 상위 `_RECALL_CANDIDATE_LIMIT`개만 평가한다. S4는 최대 `_SEGMENT_DIVERSITY_ROUNDS`라운드 동안 라운드별 상위 `_RECALL_CANDIDATE_LIMIT`개 segment를 가져오고, 이미 후보에 든 세션은 SQL 단계처럼 다음 라운드에서 제외한다. `_SEGMENT_CANDIDATE_SESSIONS`개 세션에 도달하거나 라운드 결과가 비면 멈춘다. 후보 세션의 점수는 leave-one-out을 반영한 전체 segment의 최고 유사도로 계산하고, 페널티는 세션 전체 segment 수를 기준으로 적용한다. 어느 모드든 후보 풀 밖 정답의 rank는 `None`이며 미검색으로 계산한다. limit과 다양성 상수는 `pg_recall`에서 공유한다.
