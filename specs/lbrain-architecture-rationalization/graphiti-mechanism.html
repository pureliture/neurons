LBrain architecture guide

Graphiti는 그래프 DB가 아니라, 그래프를 만드는 사서다

대화와 문서처럼 정리되지 않은 정보를 읽고, 엔티티·관계·시간·근거를 뽑아 그래프 DB에 저장한 뒤 검색 결과를 조립하는 과정을 단계별로 살펴봅니다.

● 목표 아키텍처: Graphiti 유지 · Neo4j 유지 · Graph-first 조회 · AST/Graphify 제외
이 페이지는 목표 운영 경로를 설명합니다. 현재 public brain.resolve의 Graph-first router, PostgreSQL authority join, graph_projection_outbox writer/consumer는 cutover milestone로 남아 있습니다.

각 부품은 무슨 일을 하나?

가장 많이 생기는 오해는 Graphiti와 Neo4j를 같은 부품으로 생각하는 것입니다. 둘은 함께 작동하지만 담당하는 일이 다릅니다.

애플리케이션 계층

Graphiti

대화에서 “누가 무엇을 언제 말했는가”를 읽고 엔티티, 관계, validity, provenance를 만드는 사서입니다.

그래프 저장·질의 계층

Neo4j

Graphiti가 만든 노드와 엣지를 저장하고 “A에서 B까지 어떤 경로가 있는가?”를 찾는 그래프 창고입니다. 이번 결정에서는 Neo4j를 그대로 유지합니다.

의미 검색 계층

Gemini Embedding 2 + pgvector

문장을 숫자 벡터로 바꾸고, 의미가 비슷한 메모리를 빠르게 찾습니다. Gemini Embedding 2의 full output 3072차원을 유지하고 PostgreSQL에는 halfvec(3072)로 저장합니다.

검색 조립 계층

Hybrid Retriever

벡터 검색, 키워드 검색, 시간 필터, 그래프 경로, 권한과 근거를 합쳐 최종 답변 후보를 만듭니다.

Graphiti와 그래프 DB의 관계

Graphiti는 그래프 DB에 명령을 내리는 클라이언트·도메인 로직입니다. 그래프 DB를 바꾸면 Graphiti가 자동으로 그대로 작동하는 것이 아니라, 새 backend driver 또는 adapter가 필요합니다.

임베딩 차원 확인

3072
Gemini Embedding 2 / Graphiti·Neo4j·PG fallback 공통 profile
  • 모델명은 Gemma Embedding 2가 아니라 Gemini Embedding 2입니다.
  • 이번 profile은 모델 full output인 3072차원을 줄이지 않습니다.
  • 일반 pgvector vector는 2,000차원 제한이 있으므로 vector(3072)가 아니라 halfvec(3072)를 사용합니다.
  • Graphiti의 Neo4j 검색과 PG fallback은 같은 model revision·distance 계약을 공유하고, Qdrant source는 이관 전에 실제 dimension을 확인합니다.
  • 3072와 다른 Qdrant vector는 임의 padding/projection하지 않고 quarantine 후 Embedding Worker가 re-embed합니다.

이번 방향에 대한 권장 결론

Graphiti

graphiti-core==0.30.1을 lock하고 유지합니다. LLM extraction은 async/bulk cold lane에서만 실행하고, 이미 투영된 graph read는 hot path에서 사용합니다.

Neo4j

Neo4j를 그대로 유지하며 Graphiti의 주 graph backend로 사용합니다. 대부분의 관계·multi-hop 조회는 Neo4j 후보에서 시작하고 PostgreSQL이 권위를 확인합니다.

Embedding

Gemini Embedding 2 full 3072차원을 유지하고 PostgreSQL에는 halfvec(3072)로 저장합니다. Qdrant는 migration/shadow 전용이며 Embedding Worker만 생성 책임을 집니다.
